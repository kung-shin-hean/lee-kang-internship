    Reference Implementation Standards

    What "Reference Implementation" Means

    The game should make a senior dev look at it and say: "this is the right way to build something."

    Object & Memory

    • Every GameObject that spawns has a pool.
    • No new allocations in hot paths (Update, physics callbacks, frequently-called coroutines).

    Unity Lifecycle

    • No logic in constructors. No cross-frame side effects in Awake.
    • Dependencies injected — not resolved with Find or GetComponent in Update.

    Architecture

    • Systems are decoupled — audio doesn't know about gameplay, UI doesn't know about game logic.
    • Code reads like documentation — names describe intent, methods do one thing.

    Build Quality

    • UCB produces a clean Windows IL2CPP build. If it only runs in the editor, it doesn't count.
    • link.xml stub in place to prevent IL2CPP stripping (expand per UPM).

    Package Standards (per UPM)

    • TDN (Technical Design Note) approved by Lucian before any code is written.
    • Lucian rejects bug reports missing: severity (1–3), reproducibility (always/sometimes/once), steps-to-reproduce.
    • After each UPM integration: write a structured note — 3 things that worked, 2 friction points, 1 suggestion.
    • API documentation is Lee Kang's responsibility for every UPM he integrates.
